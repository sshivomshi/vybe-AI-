# Android Studio development

Open the **whole Offline AI chatbot folder** in Android Studio (File > Open), not only its android subfolder. The root settings.gradle includes the `android` application module. Use Project view to see frontend, backend, and scripts alongside Android sources.

## Standalone internet chat (default since v2.0)

Choose the android debug variant and Run. The app starts with a native chat interface; it no longer needs Vite, a PC backend, or USB forwarding to chat. Open API setup, enter a Chat Completions compatible HTTPS base URL, model ID, and your own API key. Save the connection and send a message. Wi-Fi or mobile data is required for replies. Chats are saved in SQLite on the phone; tap Save reply to bookmark an answer, then Menu > Saved replies to find it offline.

Native app files: MainActivity.java (UI), ChatApi.java (HTTPS), PhoneStore.java (SQLite), ApiSettings.java (Keystore encryption), all under android/src/com/mnemos/mobile. Use Android Studio Run/Debug and Apply Changes when supported. Native Java changes do not use Vite HMR.

The previous React interface remains available under Menu > PC live preview (optional). Only that preview uses the instructions below.

## Optional PC preview: run and debug

1. Let Gradle sync. Use Android Studio's embedded JDK (17+; Gradle 8.9 supports JDK through 22). SDK platform 35 is required. This machine's SDK location is already in ignored local.properties.
2. Choose the `android` module and `debug` build variant. The debug package is `com.mnemos.mobile.dev`, so it can coexist with the previously installed normal APK.
3. Start the PC backend in a terminal from the project root, if it is not already running:
   ```powershell
   .\scripts\start.ps1 -WithModel
   ```
4. Connect and authorize your USB-debugging phone, or start an Android emulator. In a second root terminal run:
   ```powershell
   .\scripts\start_android_dev.ps1
   ```
5. Select the device in Android Studio and click Run or Debug. Keep both terminals running. If multiple devices are attached, add `-Serial <device-id>` to the script.
6. After reconnecting USB or starting an emulator later, refresh both port mappings without starting another Vite instance:
   ```powershell
   .\scripts\start_android_dev.ps1 -ConnectOnly
   ```

## Which changes update live?

| Change | Where | How to see it |
|---|---|---|
| React UI and CSS | frontend/src | Save; Vite hot updates the debug app. Some edits reload the page and reset unsent state. |
| Android Java | android/src/com/mnemos/mobile/MainActivity.java | Set breakpoints and use Debug. Use Apply Changes when supported, or Run again. |
| Android resources/manifest | android/res and android/AndroidManifest.xml | Rebuild and Run. |
| Python API | backend | Restart the backend after saving. Stop the existing backend before starting another against the same database. |

For automatic Python reload, stop the existing API process and run `.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload --reload-dir backend`. The model and sync services must remain running separately. Backend restarts can interrupt active requests.

The optional PC preview in debug builds loads http://127.0.0.1:5173. Vite forwards /api calls to PC port 8000. ADB reverse forwards 5173 (including the HMR WebSocket) and 8000. Release builds load PC port 8000 and do not enable WebView debugging.

## Inspect web UI

On the PC, open `chrome://inspect/#devices` in Chrome or `edge://inspect/#devices` in Edge, then inspect the Mnemos WebView. Debug builds enable WebView inspection; use Console and Network to diagnose frontend errors. Android Studio breakpoints and Logcat cover Java/native behavior. Chrome/Edge DevTools covers React/JavaScript. This app uses WebView, not Jetpack Compose Live Edit.

## Build from the terminal

```powershell
.\gradlew.bat :android:assembleDebug
```

Output: `android/build/outputs/apk/debug/android-debug.apk`.

Release APKs generated by Gradle are unsigned until you configure release signing in Android Studio. The existing `scripts/build_android.py` remains available for locally signed testing APKs connecting to port 8000.

The standalone app calls your configured internet provider directly. The optional PC preview still uses the PC backend and model. Neither mode packages an AI model for on-phone inference.

## Android Studio sync: Invalid argument: connect

If Studio also reports "Cannot start internal HTTP server", its Java networking may be failing before Gradle can sync. On this machine the logs showed `UnixDomainSockets.connect0` and `Unable to establish loopback connection` after Studio was launched from Codex. The Gradle debug build itself was successfully verified separately.

Save your edits, fully exit Android Studio, and open Android Studio yourself from the Windows Start menu. Reopen this project root and choose File > Sync Project with Gradle Files. This checks whether Studio inherited the command runner's restricted process environment. Do not launch the replacement instance from Codex. If the error persists after a normal Start-menu launch, inspect the new idea.log before changing firewall or project settings.
